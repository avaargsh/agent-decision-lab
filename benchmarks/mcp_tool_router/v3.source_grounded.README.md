# MCP Tool Router v3 — source-grounded near-neighbour corpus

This corpus is the next step after the v2 synthetic smoke seed.

It is still **not production traffic**. The user requests are authored benchmark
utterances, but every gold label is grounded in an upstream AWS Labs MCP tool
contract at the pinned revision:

`5abe7e82ba70556f80d2f42558d63a20aa3ce56c`

## Why v3 exists

v2 used four broad tools whose responsibilities were far apart. v3 deliberately
puts semantically adjacent tools in the same candidate set:

- Prometheus: instant query / range query / metric discovery / workspace discovery
- CloudWatch Logs: direct query / multi-region batch / result polling / log-group analysis
- EKS: resource listing / pod logs / events / metrics / write-capable resource management
- AWS Documentation: search / full-page read / section read / table search / recommendations

This makes candidate selection materially harder and creates meaningful
ambiguity/risk labels.

## Size and split

- calibration: **20** cases
- test: **20** cases
- 5 cases per domain per split
- calibration and test intents are disjoint
- all gold labels are covered by the presented candidate set

## Annotation contract

Every case uses `mcp-routing-label/v1` and records:

- `coverage`: covered / missing_candidate / unsupported
- `ambiguity`: clear / near_neighbor / underspecified / multi_valid
- `automation_risk`: low / medium / high
- `operation_effect`: read_only / sensitive_read / write_capable / unknown
- `expected_abstain`
- `label_basis`
- `gold_rationale`
- exact upstream evidence reference(s)

For this first v3 slice all cases are covered single-gold decisions. Explicit
underspecified, multi-valid, missing-candidate and unsupported abstention cases
will be kept in a separate extension so the closed-set quality measurement does
not silently mix with abstention semantics.

## Risk interpretation

- **low**: ordinary read-only information retrieval where autonomous routing has
  limited direct side effect
- **medium**: sensitive operational reads such as logs/events, where choosing the
  wrong tool can expose or retrieve materially different operational data
- **high**: write-capable or mutating operations. A correct router choice does
  not itself authorize execution; policy/authority remains a separate plane.

The validator rejects high-risk cases that are not marked write-capable and
rejects write-capable cases marked low risk.
