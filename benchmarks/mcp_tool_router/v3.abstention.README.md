# MCP Tool Router v3 — explicit abstention corpus

This file contains **16 test-only expected-abstain cases** designed to keep
different rejection semantics separate.

Distribution:

- 4 `underspecified`
- 4 `multi_valid`
- 4 `missing_candidate`
- 4 `unsupported`

All cases use the same frozen AWS Labs MCP identity source as the v3
source-grounded closed-set corpus.

## No fake gold labels

`underspecified`, `multi_valid`, and `unsupported` cases set
`gold_candidate: null`.

They are valid only for abstention/selective-execution evaluation. Closed-set
Accuracy/ECE calibration code rejects them explicitly.

`missing_candidate` cases retain the omitted gold identity so the benchmark can
prove that the correct upstream capability exists but is absent from the
presented candidate set.

## Plausible candidates

Ambiguous covered cases record `plausible_candidates` with at least two
presented tool identities. This is evidence that the abstention label comes from
non-uniqueness/underspecification rather than from a missing capability.

## Metric use

Use these cases for:

- False Accept Rate (FAR) over expected-abstain cases
- unsafe automation rate
- threshold transfer from the source calibration split

Do not include them in ordinary single-gold Accuracy, Macro-F1, NLL, Brier, ECE,
or temperature fitting.
